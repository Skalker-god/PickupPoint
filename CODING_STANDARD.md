# Стандарт кодування проєкту PickupPoint

## 1. Загальні положення

1. Стандарт діє для всіх файлів `.cs` у рішенні PickupPoint.
2. Мова коду (імена типів, методів, змінних) — англійська.
3. Мова коментарів і повідомлень, які бачить користувач, — українська.
4. Платформа — .NET 10, мова — C# (`LangVersion` = latest), `Nullable` увімкнено.
5. Кожне порушення стандарту, яке не можна виправити, потребує письмового обґрунтування
   в `.editorconfig` або в атрибуті `SuppressMessage`.

## 2. Іменування

| Сутність | Конвенція | Приклад | Антиприклад |
|---|---|---|---|
| Клас, запис | PascalCase, іменник | `PickupOrderLine` | `pickuporderline` |
| Інтерфейс | I + PascalCase | `IOrderRepository` | `OrderRepository` |
| Метод | PascalCase, дієслово | `CalculateTotal` | `calc` |
| Властивість | PascalCase, іменник | `UnitPrice` | `GetUnitPrice` |
| Приватне поле | _ + camelCase | `_lines` | `m_Lines` |
| Локальна змінна | camelCase | `totalAmount` | `ta` |
| Константа | PascalCase | `MaxLineCount` | `MAX_LINES` |
| Перелічення | PascalCase, однина | `PickupStatus` | `PickupStatuses` |

Додатково: скорочення на кшталт `usrCnt` заборонені, ім'я файлу збігається з іменем типу.

## 3. Форматування

1. Відступ — 4 пробіли; табуляція заборонена.
2. Довжина рядка — не більше ніж 100 символів.
3. Фігурні дужки — стиль Allman, обов'язкові навіть для однієї інструкції в тілі `if`.
4. Між членами класу — рівно один порожній рядок.
5. Директиви `using` — на початку файлу, системні перші, невживані видаляються.
6. Простір імен — файлового рівня (`namespace X;`).
7. Файл завершується порожнім рядком, пробілів наприкінці рядків немає.

## 4. Коментарі та документація

1. Коментар пояснює «чому», а не «що».
2. Кожен публічний член бібліотеки має XML-документацію (`/// <summary>`)
   — вимога набуває чинності з ЛР № 4.
3. Закоментований код у репозиторій не потрапляє.

Приклад:

```csharp
// погано: коментар переказує код
// збільшуємо лічильник на одиницю
count = count + 1;

// добре: коментар пояснює причину рішення
// склад округлює вагу вгору, тому й тут Ceiling
weight = Math.Ceiling(rawWeight);
```

## 5. Структура проєкту

1. Уся логіка предметної області — у `PickupPoint.Core`; `Console.*` там не викликається.
2. Введення й виведення — лише в `PickupPoint.App`.
3. Один публічний тип — один файл; доменні типи лежать у теці `Domain`.
4. Каталоги `bin` і `obj` не потрапляють до репозиторію.

## 6. Правила комітів

1. Повідомлення — наказовий спосіб, за конвенцією Conventional Commits:
   `тип: коротка суть` (типи: `feat`, `fix`, `docs`, `chore`, `style`).
2. Один коміт — одна завершена зміна; після коміту проєкт компілюється.
3. Повідомлення на кшталт «зміни», «фікс», «asdf» заборонені.

## 7. Правила, закріплені машинно

| Формат коду загалом | dotnet format | IDE0055 |
